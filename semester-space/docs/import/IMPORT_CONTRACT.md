# Local document import contract 0.2.0 — prospective

This contract is for a new local draft layer; engine contract remains 1.1.0. Functions/types below are **to be implemented**, not current exports. Read IMPORT_TYPES.d.ts for exact shapes. The user authorized document-first onboarding; existing Model schema, A callbacks and calculation functions remain unchanged.

Version0.2 adds the user's four further calendar examples and declared Q3/Q23 groups. See CALENDAR_FORMAT_CORPUS.md and CALENDAR_FORMAT_REFERENCE.json. The import contract is prospective: this changes draft types, not the accepted engine/model/callback contract. Existing Codex work must receive the bounded update without resetting implementation.

## Functions

- `extractDocuments(request): Promise<ImportDraft>` accepts bytes/metadata for timetable and academic calendar, selected section, AbortSignal and optional progress callback. It reads files genuinely, returns source evidence and review draft; never persists, calls planning or uploads. Expected unsupported/unreadable input returns a corresponding import status with issues. Abort rejects with AbortError and publishes no late draft. Unexpected exceptions are visible errors, not successful extraction.
- `validateImportDraft(draft, options): {ok:boolean,issues:ImportIssue[]}` checks structure, provenance, date/time validity, section coverage, group resolution, references, reviewed row treatment, explicit units and relevant calendar uncertainties. It is pure/read-only. Warnings alone do not imply an engine verdict. Critical unresolved fields yield errors; a manually toggled issue flag cannot bypass validation.
- `compileConfirmedImport(draft, options): {ok:boolean,model:Model|null,issues:ImportIssue[]}` validates first, returns no Model on errors and produces an uninitialized schema-1 initial Model on success. It does not evaluate attendance or save. A's existing `onReplaceSetup({model})` performs real expansion/validation/evaluation and overwrites the snapshot clock placeholder.

Source role, SHA, one-based page, raw extracted text and optional normalized bounding box accompany interpreted rows. OCR confidence may be null; never fabricate or interpret it as accuracy. All draft data is JSON-serializable except input bytes/signal/progress handles, which never enter a Model. Stable IDs are assigned once per extracted row; editing names or rerendering must not regenerate identity.

Import statuses are REVIEW_REQUIRED, UNREADABLE, UNSUPPORTED, separate from the six PlanStatus values. A successful extraction always starts unreviewed. Runtime progress uses READING, EXTRACTING_TEXT, RENDERING, OCR, ASSEMBLING; none means planning success.

## Review rules

1. Select the Section Q table and exclude Section R on the same page plus all other sections. Unknown section returns a reviewable issue; do not substitute the nearest label. Detect a moved section/table by structure; page2 coordinates are evidence for this fixture, not a universal location.
2. Preserve per-period text/geometry, merged labs, aliases and group alternatives. Rooms, teachers and lunch cells are not subjects. Two adjacent Communication Skills periods remain two atomic occurrences unless student explicitly confirms another attendance rule. Alternative lab staff rows are not separate simultaneous meetings.
3. Keep candidates for theory and practical registers distinct. Group choices are per applicable block; declaring Q1/Q2/Q3 does not decode Q12/Q23 automatically. Alias proposals are reviewable; duplicate names cannot silently merge identity.
4. All attendance-bearing occurrences need explicit positive integer weight; do not infer from duration. Counts and R/T/B come from page3, never from file content by guess. An unused/excluded candidate register is removed from the *draft* before counts mapping; existing saved registers are never changed.
5. Every Library/NCC/Sports occurrence needs explicit treatment before compilation. Confirmed zero-unit compulsory weekly obligations become independent Event occurrences, with no attendance Session/register. Their dates honor confirmed holiday/replacement rules; test this against public engine expansion for equivalent effective weekdays. Never fake a positive-weight session to store a zero-unit event. Lunch is a break, not a compulsory event or register.
6. Calendar rules distinguish holidays, boundaries, tentative exam windows, student activities and administrative information. Administrative review meetings do not become student compulsory events automatically. Present other extracted activity rows in a secondary review list; low-confidence/unknown student obligations remain unresolved, not discarded.
7. Validate real Gregorian dates, date ordering, weekday/year consistency and academic context. Flag OCR 2028 against a 2026 holiday/weekday; require visible correction from the source. Do not silently replace the year using filename context. Institution dates, first-year start, timetable-effective start, last ordinary class and examination exceptions remain separate fields until confirmed.
8. Relevant unresolved exam/compulsory windows prevent compilation into a passing planner setup. A student may confirm precise occurrences, explicitly choose whole-window full-day protection or confirm non-applicability. Preserve TENTATIVE/UNSPECIFIED wording until resolved. Exams do not delete classes; cancellation needs explicit confirmation. Out-of-horizon informational windows do not extend projection.
9. Use grouped confirmation for clear reviewed timetable/date rows; do not force 85 administrative checkbox decisions. Explicitly surface exceptions and critical ambiguous entries. Global "looks good" cannot override missing units/groups/counts/dates.

## Compilation

Use confirmed startDate/teachingEnd and selected section/context. Build Course objects with mustAttend from selected subject IDs; register IDs map exactly to selected candidate registers and supplied rule/count maps. Preserve six PlanStatus literals and all four engine exports. Positive-weight weekly patterns go in Schedule.weeklyTemplates; initial schedule.initialized=false; actual sessions start empty. Confirmed recurring zero-unit obligations and confirmed calendar compulsory dates become independent Events via adapter date expansion. Test holiday/replacement interactions; do not reimplement attendance arithmetic or greedy planning.

Construct one confirmed Snapshot with unchanged submitted date/counts and completeToday flag; confirmedAt is only `clockPlaceholder`, never extraction time or inferred historical provenance. A restamps the initial snapshot. Initial revision0, no commitments; attendanceConfirmation.throughDate equals snapshot date as in existing setup. No imported projected counts. Context preparedOn may use placeholder local date; applicability must be explicitly true. Preferences remain existing typed values.

Only after successful compilation call onReplaceSetup exactly once. If A rejects it, keep the draft and show its actual error. Never mark setup saved from compile success alone. Cancel or parser failure must leave prior state unchanged. Existing model means import cannot initialize/replace it. Raw files and draft are memory-only and not retained by the storage envelope.

## Operational bounds

Initial supported types: PDF, PNG, JPEG. Proposed limits: 15MB per file, 20 pages per PDF; reject visibly without truncation. Actual files are 675491 and 4570262 bytes, four/eight pages. Process OCR page-by-page with one worker initially, bounded rendering (start at <=2200px long edge), progress and cancellation; measure quality/performance before changing limits. Release worker, canvas and object URLs. A selected source replacement increments a job token so old results cannot win a race.

Self-host PDF/OCR runtime assets and language data; pin dependencies and include licenses. No runtime external API/CDN, GPU, secrets or backend. Tools/build.mjs may copy required assets from pinned packages to dist; tools/serve.mjs may add needed MIME types without exposing source metadata. Missing assets must produce actionable failure. Do not rewrite the framework or change production origin/audience.

## Additional format rules — 0.2

- User-declared active scope: MAIT, Section Q, general practical subgroup Q3 and programming practical label Q23. This resolves declared choices only. Q's physics block lists Q1/Q2; Q3 physics mapping remains unresolved. Do not use another institution's calendar to complete missing MAIT data.
- The four new examples are FORMAT_TEST_ONLY: one two-page IIT(BHU) PDF and three calendar images with unverified institution identities. Alongside the prior scanned MAIT calendar there are five calendar documents, not five validated institutional templates. These are development/regression references, not independent held-out tests or learned model weights.
- Keep document institution, academic year, selected term and cohort applicability separate. Match sourceApplicability and academicScope against confirmed context before compilation. A cropped screenshot has unknown institution unless the student confirms it. Different uploaded source documents are never merged just because dates look similar. UG/PG/PhD, first versus later semester, and UG-except-TA conditions can change applicability. Missing role data leaves affected entries unresolved.
- In a dual-term table, use the selected term's column for every row and footnote. First-year and all-other commencement rows are alternatives, not a combined date range. "To be announced", "to be decided", empty cells and dashes remain unknown/not applicable; they are not holidays. Faculty-only vacation does not imply student vacation.
- Parse date grids using month/week geometry, year rollover, explicit ranges, legend and footnotes together. Omitted Sundays do not shorten a printed exam range. Superscript teaching counters are not dates or weights. When a legend is cropped/missing, ambiguous colours/codes remain unresolved. Colours distinguish source categories; never label every orange/red/green cell a gazetted holiday or compulsory event. If monochrome input removes critical legend evidence, request review instead of claiming equivalent certainty.
- Recognize replacement weekday statements in grids AND notes. Store source date separately from replacementWeekday (ISO1=Monday..7=Sunday). A Saturday using Monday's timetable is valid, not a weekday-date mismatch. A working Saturday for examinations with no pattern is WORKING_DAY_NOTICE; do not invent Monday or ordinary Saturday classes. Explicit replacement substitutes exactly once; it does not add both date-weekday and replacement patterns.
- Compile confirmed NON_TEACHING ranges to labelled Schedule.holidays suppression dates; reserve their labels for the source reason (recess/NT/class suspension), not a fabricated gazetted-holiday name. A corresponding makeup date goes to Schedule.replacements. If teaching is explicitly on a suppressed date, require existing holidayTeachingDates confirmation and retain both markers. A general college event does not suppress teaching unless the source explicitly says so and applicability is confirmed.
- Preserve uncertainty from the source itself. IIT(BHU) has visible weekday/date conflicts and a Hindi/English year disagreement. Distinguish text-layer encoding failure (the Hindi page extracts as legacy Latin glyph codes) from an empty scan; English page is a usable alternative. Avoid double-counting bilingual duplicate records. If Hindi-only extraction is unsupported, say so; no automatic Hindi OCR expansion is authorized. A conflicting bilingual value requires review, not silent preference for a convenient page.
- Review relevant events overlapping the future projection interval (after the confirmed snapshot through teachingEnd). Past or out-of-horizon administrative conflicts may remain visible warnings; they must not manufacture future obligations or expand the horizon. Unknown teaching-end dates are not inferred from the first examination date or vacation start.
